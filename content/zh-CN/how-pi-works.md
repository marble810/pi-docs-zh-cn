# Pi 的工作原理｜ How Works

Pi 协调模型请求、工具执行、上下文组装和会话存储。会话是 Pi 对一次对话的记录，包括消息、工具调用及结果、模型变更、上下文压缩以及其他事件。

会话中的消息和事件构成一棵树。穿过该树的每条路径都是一个分支。终止于当前条目的分支是活动分支，并为下一次模型请求提供历史记录。

## 代理循环｜代理 loop

提交的消息会被添加到活动分支。Pi 根据系统提示词、活动分支、可用工具和模型设置构建模型请求，然后通过选定的模型提供商发送。

模型提供商流式返回助手响应，其中可能包含文本和工具调用。Pi 记录该响应，执行每个工具调用，并记录结果。这就完成了一轮。如果工具结果或排队的消息需要另一次模型请求，Pi 会开始另一轮。否则，运行结束。

引导消息在当前助手轮次之后进入。后续消息在代理完成其待处理工作后进入。中止会停止当前运行，并将排队的消息返回到编辑器。

## 上下文｜ Context

活动分支提供对话历史。Pi 将其会话条目转换为 model-compatible 用户、助手和 tool-result 消息。

Pi 根据其基础指令和发现的上下文文件构建系统提示词。请求还携带工具定义和技能描述。

完整的技能指令按需加载。扩展可以添加指令或转换上下文。

提示词模板在编辑器输入成为用户消息之前对其进行展开。选定的文件、图像、粘贴的文本和 shell 输出可以成为消息内容。

## 会话｜ Sessions

持久会话是 JSONL 文件。每个树条目都有一个 ID ，并引用其父条目。当前条目标识活动分支。

从较早的条目继续会在同一文件中创建另一个分支。分叉和克隆会将选定的历史记录复制到新的会话文件中。

模型上下文从活动分支重建。上下文压缩会插入一个摘要条目，在后续模型请求中替换较早的消息。原始条目仍保留在会话树中。

## 接口｜ Interfaces

交互模式在终端中渲染会话和代理事件。打印模式运行提示词并写出最终响应。JSON 模式将代理事件写为 JSONL。

RPC 模式在 stdin 上接受 JSONL 命令，并将响应和事件写入 stdout。TypeScript SDK 在进程内创建和控制代理会话。

所有接口都使用相同的代理和会话机制。

## 扩展和资源｜ Extensions and resources

扩展是加载到 Pi 进程中的 TypeScript 模块。它们的工厂函数会注册工具、命令、快捷键、模型提供商、事件处理器、渲染器和终端 UI。

技能提供 on-demand 指令和支持文件。提示词模板提供可复用的消息文本。主题提供终端颜色。Pi 包通过 npm or git 分发这些资源。

## 信任与权限｜ Trust and permissions

Pi 在加载项目设置和资源之前先解析项目信任。在信任决策和 project-resource 加载之后，Pi 加载上下文文件。启用的工具使用 Pi 进程的 operating-system 权限。扩展在该进程内执行。
